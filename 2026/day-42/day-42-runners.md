# Day 42 – GitHub-Hosted & Self-Hosted Runners

## 1. What is a Runner?

A **runner** is a machine that executes jobs in a GitHub Actions workflow.

There are two types:

- **GitHub-hosted runner:** A virtual machine managed by GitHub.
- **Self-hosted runner:** A machine managed by the user or organization.

---

## 2. GitHub-Hosted Runners

GitHub provides virtual machines with different operating systems.

### Common runner labels

```yaml
runs-on: ubuntu-latest
runs-on: windows-latest
runs-on: macos-latest
```

### Practical: Run jobs on three operating systems

Created `.github/workflows/runners.yml`.

```yaml
name: GitHub Hosted Runners

on:
  push:

jobs:
  ubuntu-job:
    runs-on: ubuntu-latest
    steps:
      - name: Print operating system
        run: 'echo "Operating System: ${{ runner.os }}"'

      - name: Print hostname
        run: hostname

      - name: Print current user
        run: whoami

  windows-job:
    runs-on: windows-latest
    steps:
      - name: Print operating system
        run: 'echo "Operating System: ${{ runner.os }}"'

      - name: Print hostname
        run: hostname

      - name: Print current user
        run: whoami

  macos-job:
    runs-on: macos-latest
    steps:
      - name: Print operating system
        run: 'echo "Operating System: ${{ runner.os }}"'

      - name: Print hostname
        run: hostname

      - name: Print current user
        run: whoami
```

### Important commands

| Command | Purpose |
|---|---|
| `hostname` | Displays the machine hostname |
| `whoami` | Displays the current user |
| `${{ runner.os }}` | Displays the runner operating system |

### Practical Result

- Ubuntu job: Successful
- Windows job: Successful
- macOS job: Successful

All three jobs ran successfully in the same workflow.

### What is a GitHub-hosted runner?

A GitHub-hosted runner is a virtual machine managed and maintained by GitHub. It provides an environment to execute GitHub Actions jobs.

## 3. Explore Pre-Installed Software

GitHub-hosted runners come with many commonly used developer and DevOps tools.

### Practical commands

```yaml
- name: Check preinstalled tools
  run: |
    echo "Docker version:"
    docker --version

    echo "Python version:"
    python3 --version

    echo "Node.js version:"
    node --version

    echo "Git version:"
    git --version
```

### Actual output from my Ubuntu runner

| Tool | Installed version |
|---|---|
| Docker | 29.4.2 |
| Python | 3.14.4 |
| Node.js | v24.22.3 |
| Git | 2.56.1 |

### Why are pre-installed tools important?

- Reduce installation and configuration time.
- Make CI/CD workflows faster.
- Provide commonly used development tools.
- Help developers focus on building and testing applications.

**Official documentation:**

https://github.com/actions/runner-images

Note: Runner images and installed software versions can change over time.

## 4. Self-Hosted Runner

A **self-hosted runner** is a physical machine or virtual machine that we configure to execute GitHub Actions jobs.

Examples:

- Local Linux machine
- AWS EC2 instance
- Cloud VM
- VPS

### GitHub setup steps

1. Open your GitHub repository.
2. Go to Settings.
3. Open Actions → Runners.
4. Click New self-hosted runner.
5. Select Linux.
6. Select x64 architecture.
7. Follow GitHub's download and configuration instructions.
8. Start the runner.
9. Verify that it appears online and idle.

### Basic runner setup commands

```bash
mkdir -p ~/actions-runner
cd ~/actions-runner
```

Download the runner package using the exact command generated by GitHub.

Extract the downloaded package:

```bash
tar xzf actions-runner-linux-x64-<version>.tar.gz
```

Configure the runner using the temporary registration token generated by GitHub:

```bash
./config.sh
```

Start the runner:

```bash
./run.sh
```

Keep the terminal running while the runner is being used.

**Important:** Never share your registration token. A self-hosted runner needs proper security because workflow commands can access resources available to its local user.

## 5. Use a Self-Hosted Runner

Create `.github/workflows/self-hosted.yml`.

```yaml
name: Self Hosted Runner

on:
  workflow_dispatch:

jobs:
  runner-test:
    runs-on: self-hosted

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Print hostname
        run: hostname

      - name: Print working directory
        run: pwd

      - name: Create and verify file
        run: |
          echo "Created by GitHub Actions" > runner-test.txt
          cat runner-test.txt
          test -f runner-test.txt
          echo "File created successfully!"
```

The file is created in the runner's workspace on the self-hosted machine.

## 6. Runner Labels

Labels help GitHub identify which self-hosted runner should execute a job.

Example:

```yaml
runs-on: [self-hosted, linux, my-linux-runner]
```

All specified labels must match the runner.

### Why are labels useful?

- Identify different runner environments.
- Select runners with specific operating systems.
- Select machines with particular tools or hardware.
- Manage multiple self-hosted runners.

---

## 7. GitHub-Hosted vs Self-Hosted Runners

| Comparison | GitHub-Hosted | Self-Hosted |
|---|---|---|
| Who manages it? | GitHub | User/organization |
| Cost | Uses GitHub Actions plan and included usage allowances | Own hardware or cloud infrastructure costs |
| Pre-installed tools | Many common tools | User installs and manages tools |
| Good for | General CI/CD workflows | Custom environments and infrastructure |
| Security concern | GitHub manages the runner infrastructure | User manages machine security and access |

### When should we use them?

**GitHub-hosted runners:**
- General CI/CD pipelines.
- Testing applications on different operating systems.
- Projects that need a managed environment.

**Self-hosted runners:**
- Custom software requirements.
- Access to private infrastructure.
- Special hardware or configuration requirements.

## 8. Important Learning Points

1. A runner is the machine that executes a GitHub Actions job.
2. GitHub-hosted runners are managed by GitHub.
3. Self-hosted runners are managed by users or organizations.
4. `runs-on` specifies which runner environment to use.
5. GitHub-hosted jobs can execute in parallel.
6. Pre-installed tools reduce workflow setup time.
7. Labels help select specific self-hosted runners.
8. Self-hosted runners require careful security management.
